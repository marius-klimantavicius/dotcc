## Outcome and scope

Translate CPython's actual C parser, compiler, evaluation loop, object model,
reference counting, cyclic collector, import machinery and selected built-in
modules into `TranslatedCPython`. Python source and standard-library Python code
execute on that translated interpreter. Use DotCC.Libc and explicit managed host
services for execution facilities, with a thin owning .NET embedding API and a
separate consumer. Native CPython is a build tool and test oracle only.

The first useful workflow reads a UTF-8 JSON file containing `{"items":[2,3,5]}`,
imports an application package from a configured directory, calls a registered
managed `host.double` function for each item, and writes exactly
`{"sum":20,"values":[4,6,10]}` using Python's `json` module with fixed separators
and sorted keys. The consumer checks three callbacks, exact file bytes, a Python
function return value, captured output, and a separately raised/caught exception
with a traceback. It releases all owned objects, finalizes, and repeats with a
fresh runtime. The workflow must run without an installed Python executable,
native libpython, or an ambient host standard library.

## Generated code simplification and constant data

User-required updates, 2026-10-17 and 2026-10-18. These are completion requirements for the
ongoing campaign, not optional cleanup after acceptance. Implement them in the
shared emitter/linker or semantic postprocessor, with the current compiler owner
coordinating changes. Do not hand-edit generated CPython or patch upstream macros
to obtain a prettier result. Preserve the completed startup/initializer repairs.

**Reuse repeated address calculations.** The user identified repeated expressions
of this shape, with an actual generated anonymous type in place of `AnonType`:

```csharp
(AnonType*)&(*(pyruntimestate*)global::System.Runtime.CompilerServices.Unsafe.AsPointer(
    ref global::Managed.Interpreters.CPython.Globals._PyRuntime))
```

Simplify redundant address/dereference/cast layers where their types and semantics
permit, then compute repeated stable base addresses or typed projections once
in a suitably scoped local. Use that local across the relevant statements rather
than repeating the entire expression. Prefer generating reusable base locals
directly when emitting aggregate initialization; use semantic analysis for broader
common-expression reuse. Keep locals within initializer helper boundaries so
this work does not recreate oversized methods or argument lists.

Macro origin is not itself a restriction: preprocessing has already expanded the
expression before C# emission. The actual restrictions are evaluation order and
frequency, side effects, control-flow reachability, changed aliases/base values,
volatile/atomic reads, TLS/runtime ownership and pointer lifetime. Cache an
address, not a mutable field value. Never hoist an access onto a previously
unexecuted branch or retain an unpinned managed address across a GC safepoint.
Use a tracked by-reference local or correctly scoped pin where appropriate;
reuse an unmanaged pointer only where stable storage/lifetime is established.
Record concrete unsafe cases left unchanged, rather than a blanket macro exemption.

**Emit readable array and record initialization.** Apply the techniques documented
in the existing [EDG storage/readability guide](../../edgcpp/docs/source-storage-readability.md),
adapting them to this backend's storage and lifetime model. The reference
implementations are [record initialization](../../edgcpp/backend/dot_gen_record_data.h)
and [primitive data](../../edgcpp/backend/dot_gen_primitive_data.h); their historical
passes are design references, not CPython acceptance evidence.

Use one source-named typed destination alias for each relevant table or enclosing
record within its safe initialization scope. Cover ordinary, pointer and
function-pointer arrays, nested tables, static-local backing storage and TLS;
retain per-owner/per-thread isolation and avoid generated-local name collisions.
Eligible small record elements use indexed target-typed value initializers:

```csharp
table[0] = new()
{
    length = 5,
    token = 65535,
    flags = 32768,
};
```

Preserve source member names, trailing field commas and readable nested record
initializers. Omit narrow-integer casts only when C# constant conversion preserves
the exact value; retain enum and signed/unsigned boundary conversions. A `new()`
here constructs a value type, not a heap object. A single-selected-member union
may use this form when its managed layout and initialization semantics permit.
Bitfields, unsupported overlaps, array members and repeated designations retain
correct direct stores or bulk copies. Relocations, including self/forward
references, always target final storage rather than an initializer temporary.

Keep large containing aggregates such as `_PyRuntime` initialized in place.
Bound the size and complexity of each record value construction; readable rows
must not reintroduce C025/C026's oversized value temporaries, argument lists or
initializer methods. Split helpers at complete row/store/copy boundaries and
pass stable destination aliases. Repeated equal constant rows may use bounded
loops only when evaluation, relocation and zero-fill semantics are unchanged.
Where literal helpers already supply stable pointers, readable escaped previews
and removal of redundant zero offsets may improve navigation without changing
literal bytes or identity.

**Store immutable primitive initializer data in assembly data.** Replace constant-only
payloads such as `MemoryExtensions.AsSpan(new byte[] { ... }).CopyTo(...)`
with a named property and a span use, for example:

```csharp
private static ReadOnlySpan<byte> DocBytes0 => [99, 111, 109, 0];
private static ReadOnlySpan<ushort> TokenValues0 => [1, 65535, 32768];
private static ReadOnlySpan<int> SignedValues0 => [-17, 0, 42];
private static ReadOnlySpan<uint> TableValues0 => [1116352408U, 1899447441U];

// Copy into the independently owned, writable C destination.
TokenValues0.CopyTo(new Span<ushort>(destination, TokenValues0.Length));
```

This requirement extends beyond bytes to signed/unsigned 8-, 16-, 32- and 64-bit
integer tables and the backend's supported floating-point tables, including
`float`, `double` and `Half` where supported. Map C types through the selected
target ABI rather than host assumptions (`char` signedness, `long`, `wchar_t`,
enum underlying types and native-width integers). Inventory boolean/character,
native-width, wider integer and extended-float representations actually emitted
by the backend. Use a proven fixed-width backing span and typed view where a
direct `ReadOnlySpan<T>` constant getter cannot embed that representation; record
unsupported representations explicitly rather than silently allocating arrays
or narrowing values. Do not introduce new source-language type support solely
for this readability work.

Preserve floating-point data as exact bits, including signed zero, infinities,
subnormals and NaN payloads. Prefer integer-backed constant properties and an
allocation-free `MemoryMarshal.Cast` view when needed, for example:

```csharp
private static ReadOnlySpan<ulong> DoubleBits0 =>
    [0x8000000000000000UL, 0x7ff8000000000042UL];
private static ReadOnlySpan<double> DoubleValues0 =>
    System.Runtime.InteropServices.MemoryMarshal.Cast<ulong, double>(DoubleBits0);
```

Enum views similarly preserve the declared underlying width and bits. Verify
target byte order/layout for every backing/view conversion; no decimal
round-trip, NaN canonicalization or per-element conversion loop may alter data.
Pointer/function-pointer relocations remain runtime expressions, outside primitive
constant blobs. Primitive fields inside aggregate/array rows can still use bulk
copies independently of the surrounding record's fallback path.

Use deterministic names and the existing [literal-storage machinery](../../docs/literal-storage.md)
where applicable. The compiled getter must reference assembly-backed constant
data without creating a managed array on access; merely moving `new T[]`
into a property or caching it in a static array does not meet this requirement.
Audit the actual Release IL/data representation, since source syntax alone is
not proof of allocation behavior. Apply the initializer-payload change to raw
emission and preserve it through postprocessing and split/object linking.

Distinguish the immutable initializer payload from the C object it initializes.
Writable arrays still require their own writable storage and initial copy.
Separate C declarations retain their addresses, mutability, alignment and
ownership; pooling identical initializer bytes must not coalesce those objects.
Preserve exact bytes, embedded/final NULs, explicit extents, zero-fill and
allocation-before-relocation order. Existing pinned literal pools may still
