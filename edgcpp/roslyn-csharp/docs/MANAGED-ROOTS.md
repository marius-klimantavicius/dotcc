# Explicit managed definition roots

Approved follow-on contract; implementation starts after the verified pointer
checkpoint. Existing retain-all library/executable behavior remains the default.
Managed definition roots are separate from native `Exports` and do not promise
native entry wrappers. An opt-in selection request requires pinned input identity
and an exact captured linkage identity for every managed root. Public indexed name
lookup may discover bounded candidates; exact current input/linkage/definition and
signature facts uniquely select the current public FunctionSymbol. Prior report
locators are citations, not persistent binding handles. Ambiguity or a bound hit
fails before publication.

Selection precedes Inventory and ProgramAssembler all-definition body traversal.
An immutable bounded public-identity plan drives selected inventory, emitter
functions/storage, required imports and reports. Unvisited input remains explicitly
unvisited; selected-closure completion never claims a complete input translation.
The initial implementation is one input, not multi-unit linking or a replacement
for ProgramAssembly's definition policy. Default complete-definition behavior and
its previous evidence must remain unchanged.

Closure follows actual typed execution operands, selected direct calls and callee
identities, executable local/static initialization, globals and exact constant/
aggregate/address/associated-storage dependencies, function addresses and ABI roles,
throw/destructor/handler facts and required cleanup storage/condition/VTT/count
contracts. Semantic helper edges and metadata recipes are dependencies only;
recipes never become an execution schedule. Preserve both retained branches.
Unrelated class methods/vtables/typeinfo do not enter closure merely through source
metadata; an actual retained use supplies the dependency. Unknown execution,
indirect target obligations or unsupported required declarations fail closed.
Mandatory translation-unit/file initialization and teardown remain included, or
unsupported ambient execution is diagnosed explicitly rather than erased.

Use explicit closure/body/storage/operation/depth/resource limits with actual
counts and root-to-edge provenance. No whole-object scan fallback, source-name
semantic rules, internal IDs, raw database access, native application bodies or
branch pruning. Required import accounting includes every selected obligation;
providers cannot fill an omitted application definition.
