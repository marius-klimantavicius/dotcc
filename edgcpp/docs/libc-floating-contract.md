# Floating helpers and portable declarations

`backend/runtime/LibcFloat.cs` supplies allocation-free bit operations for the
translated binary32, binary64 and binary80 representations. It is a helper
layer, not a complete implementation of C's floating environment. The current
provider does not yet bind these new declarations to emitted wrappers.

The three overload families accept `float`, `double` or `Float80`:

| Method | Contract |
| --- | --- |
| `SignBit(value)` | Returns 0/1, including negative zero and signed NaNs. |
| `IsFinite(value)` | Returns 0/1 by exponent classification. |
| `Classify(value)` | Returns NaN=0, infinity=1, zero=2, subnormal=3, normal=4. |
| `Frexp(value, int* exponent)` | Exact normalized fraction in [0.5,1) in magnitude; handles subnormals with leading-zero counting. Zero and nonfinite inputs are returned unchanged with exponent 0. |
| `ScaleB(value, int power)` | Exact scaling where representable; one nearest-even rounding at a subnormal boundary, signed zero on underflow, signed infinity on overflow. Handles the full `int` exponent range using bounded integer operations. |

Scaling does not use `BigInteger`, managed arrays, or host floating arithmetic.
Classification/decomposition/scaling preserve sign and NaN payload bits in the
stored representation. Signaling-NaN exception behavior is not implemented.
Binary80 guarantees apply to canonical values generated by the translator;
this is not a promise to reproduce every x87 unsupported bit-pattern trap.

The intended import mapping is `frexp[f/l]` to the corresponding `Frexp`
overload and `scalbn[f/l]` to `ScaleB`, with public wrapper error handling.
The private `__edg_signbit[f/l]` and `__edg_isfinite[f/l]` declarations match
`SignBit` and `IsFinite`. Their macros select the original floating width using
`sizeof`, evaluate the chosen expression once, and avoid converting binary80
to double merely for classification. **Do not bind public scalbn directly and
claim completion:** these helpers neither set errno nor record floating
exception flags. Public range-error and environment semantics remain work.

## Evidence

`backend/tests/libc_float_native.c` is a synthetic native oracle for canonical
x86-64 binary80, binary64 and binary32. The repeatable verifier is
`backend/tests/libc_float_verify.py --nativeaot --output-dir <new-directory>`.

The first preserved result is
[`artifacts/campaign/libc-float-20261002-225105/results.json`](../artifacts/campaign/libc-float-20261002-225105/results.json):
**11,236 exact native vectors pass in managed JIT and NativeAOT on Linux x64**.
The vectors cover both signs, zero, smallest/largest subnormals, normal
boundaries, half-way underflow, extreme exponent arguments, overflow and
3,000 deterministic random inputs of each width. Additional managed tests
check binary80 infinity/NaN payloads and zero managed allocations over 10,000
finite helper iterations. This does not establish Windows/macOS execution,
managed directed rounding, or an integrated printf result.

## Portable headers

The selected header set now contains:

- `float.h`: fixed binary32/binary64/binary80 limits, precision, subnormal and
  decimal round-trip constants. `FLT_ROUNDS=1` describes the currently selected
  nearest-even arithmetic; `FLT_EVAL_METHOD=0` describes the generated profile.
- `inttypes.h`: LP64 PRI/SCN macros for exact, least, fast, pointer and maximum
  integer types, plus standard maximum-integer function declarations.
- `wchar.h`: signed 32-bit wchar_t, unsigned 32-bit wint_t, WEOF, an explicit
  eight-byte UTF-8 conversion-state ABI and selected conversion/string
  declarations. Wide streams and conversion implementations remain pending.
- `limits.h`: the selected UTF-8 `MB_LEN_MAX=4`; `stdlib.h` declares `wctomb`.
- `errno.h`: normalized byte-stream error constants, including EOVERFLOW and
  EILSEQ, matching the runtime's existing host-independent error numbers.

A declaration alone does not enable an external call: the central registry
continues rejecting unbound symbols. The header checks only prove definitions,
layout and constant-expression behavior, not implementations of all declared
functions. The provisional byte-stream `fpos_t` must grow before wide-stream
state is accepted.

Both `portable_integer_headers.c` and `portable_libc_headers.c` pass generated
C and C++ JIT/NativeAOT execution under the portable target (eight checks):
[`artifacts/campaign/portable-libc-headers-20261002-225421/results.json`](../artifacts/campaign/portable-libc-headers-20261002-225421/results.json).
The repeatable entry point is `backend/tests/portable_integer_headers_verify.py`.

## Rounding audit and remaining formatter gates

Existing `Float80.cs` hardcodes ties-to-even in `RoundShift`, `Pack`, division
rounding and binary32/binary64 conversions. Addition of opposite signed equal
values also follows its fixed nearest-mode sign policy. It does not accept
owner/thread rounding state or record IEEE exception flags. Converting a
binary64 NaN to Float80 currently canonicalizes it and loses its input sign.
The new direct classification helpers avoid that conversion, but do not repair
all general arithmetic or conversion contracts.

A complete floating environment therefore requires coordinated backend/runtime
work: owner/thread rounding mode and flags; mode-aware binary80 arithmetic,
conversions, overflow/underflow and cancellation; a strategy for native managed
binary32/binary64 arithmetic that cannot silently depend on ambient native
thread rounding; public fenv/errno glue; signaling-NaN policy; and JIT/AOT
synthetic differential tests for all supported modes. Do not expose a working
`fesetround` that changes only these helpers while ordinary arithmetic remains
nearest-even.

Musl's formatter infers rounding through floating arithmetic. Its native
four-mode tests prove the selected C algorithm, not current C# directed-mode
behavior. The nearest-even helper slice enables correct classification and
exponent decomposition without pretending to complete that larger gate.
