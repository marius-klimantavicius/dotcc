# Semantic export: managed C emission checkpoint

This continues the [original architecture investigation](semantic-export-investigation.md)
and [export/reader checkpoint](semantic-export-implementation.md). The new path is
original C → isolated EDG frontend → versioned semantic package → managed C#
emitter → ordinary .NET/NativeAOT build. The existing production backend remains
independent.

## Run the managed emitter

Build and export with the commands in the [exporter README](../semantic-export/README.md),
then run:

```sh
dotnet run --project edgcpp/semantic-export/managed -c Release -- \
  emit-csharp PACKAGE_DIRECTORY --output Generated.cs
```

`--class NAME` changes the default `SemanticModule` container. Compile the result
with `AllowUnsafeBlocks=true`. The emitter reads named semantic records; it does
not parse original C text, IL display output, or code generated by the old backend.
Package hashes and source availability are validated before profile validation.
Source generation completes in memory before the output file is written, so a
rejected package leaves an existing output file untouched.

## Bounded profile

`c-integer-structured/1` targets C functions with integer/void/pointer signatures,
ordinary initialized scalar locals, direct calls to definitions in the same TU,
plain record layouts, indexed/member pointer access and structured control flow.
C integer truth values and conditions are emitted in their respective contexts.
Unsigned arithmetic retains wraparound even when the consuming project enables
checked arithmetic. Exported widths determine managed integer types, including
64-bit unsigned constants. Runtime ABI checks require a little-endian 64-bit
process; no cross-platform execution claim follows from this gate.

The exporter now supplies integer and type-spelling supplements, language and
prototype facts, named qualifiers/storage classes, pragma classification,
alignment/packing and GNU cleanup/conditional facts. The simple C packages have
zero adapter diagnostics. The emitter requires zero diagnostics and separately
checks supported constructs; an empty diagnostic list alone does not permit
emission.

The graph-wide `completeForEmission` remains false. `inspect --strict-emission`
still rejects these graphs. Only the explicitly selected bounded profile can
emit them. C++, globals/TLS/static locals, external calls, arrays, bitfields,
volatile/atomic access, lifetime cleanup and other unsupported constructs must
be diagnosed rather than silently approximated.
The profile also rejects mixed-type compound arithmetic and unsigned 64-bit
unary negation until their differing C# rules have dedicated lowering.

## Verification

The [emission harness](../semantic-export/tests/emission-tests/verify.py) compiles
the exact packaged source snapshots with GCC and compares output with generated
C# under JIT and NativeAOT. It also checks deterministic emission, a reviewed
[plain-C golden](../semantic-export/tests/emission-tests/plain.golden.cs), and
rejection without creating or overwriting output. The existing semantic reader
suite retains the C/C++ overload/template/lifetime/macro assertions.

Linux x64/.NET 10 validation compares **226 observations** (21 record/indexing
cases, 195 scalar/control-flow cases and 10 pointer-condition cases) against native C under both generated
JIT and NativeAOT execution. Generated projects enable checked arithmetic and
treat warnings as errors. The full execution harness passed **81 checks**. The
NativeAOT build of the emitter passed **63 emission checks**, reproducing the
exact generated programs already verified under both execution modes and checking
output preservation on rejection. The reader suite passed **20 checks under JIT
and the same 20 under NativeAOT**, including the existing C++ semantic proofs.

The [durable evidence manifest](../semantic-export/evidence-c-emission.json)
records exact artifacts and hashes. The accepted generated source is available
in the [reviewed golden](../semantic-export/tests/emission-tests/plain.golden.cs).
Earlier build/export attempts and intermediate tests are retained alongside the
accepted evidence; only the named accepted results establish this checkpoint.

## Next work

This checkpoint establishes actual managed emission; it does not complete the
investigation's full go/no-go gate. Managed C++ lifetime lowering and differential
normal/exceptional destruction traces remain unimplemented.

Next, use reduced SQLite functions and declarations to drive C coverage: static
globals, arrays/aggregate initialization, switch/goto, named bitfields and runtime
calls. Reuse the production runtime and target profiles as those constructs are
added. Full SQLite differential execution, package-size/time/memory measurement,
source-oriented splitting and a per-TU semantic linker remain ahead. Preserve
profile rejection tests as coverage grows; do not broaden the global completeness
claim to match a small positive corpus.
