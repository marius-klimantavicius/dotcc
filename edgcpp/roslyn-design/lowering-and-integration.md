# Lowering and integration decision

Design only. All upstream citations below are paths and line numbers in pristine EDG revision `89e67e07c7f6d0fc38622f9778d8e79f40deaa0f`, inspected at `/tmp/roslynobj-edg-upstream-20261012`. No existing object backend, linker, semantic exporter, or its artifacts were used. “Verified” means verified from upstream source, not experimentally validated by a new backend build.

## Decision

Use a new backend with `DO_IL_LOWERING=FALSE`. Serialize EDG's **semantically elaborated C++ IL**, including implicit operations and lifetime obligations, directly into `.roslynobj`. This is source-shaped typed semantic IL, not a raw parser AST. EDG has already performed language lookup, overload selection, instantiation of required available definitions, initialization analysis and class layout. It need not translate classes, exceptions or member operations to C to expose these facts.

This choice is supported explicitly by upstream: lowering is optional, utilities work on either IL form, and unlowered-backend authors may use lowering as a guide (`doc/source/lower_il.rst:78–123`). The C generator remains a coverage and traversal reference; upstream calls it a testing “fake back end,” not the definition of all C++ semantics (`doc/source/c_gen_be.rst:5–9`). In particular, its portability rewrites such as dummy fields, `memcpy`, `memset`, local-type promotion and wide-string variables are not required forms for the semantic object (`doc/source/c_gen_be.rst:76–180`).

There is no verified stock “only lower what is needed for a source-shaped semantic object” pass. The global lowering switch drives a C-oriented pass. The available knobs selectively preserve a few constructs or change an ABI/runtime decision; they do not provide an independent menu of all C++ desugarings.

## Why partial exception lowering is not the primary solution

Stock lowering has three exception modes (`doc/source/lower_il.rst:2742–2775`):

| `DO_IL_LOWERING` | `DO_FULL_PORTABLE_EH_LOWERING` | `GENERATE_EH_TABLES` | Meaning |
|---|---|---|---|
| false | immaterial | forced false | Unlowered typed C++ IL and original lifetime graph. Recommended. |
| true | true | forced true | Full portable C EH; stack maintenance and setjmp-based try implementation. Rejected. |
| true | false | true | Partial EH: try/catch/throw survive, EDG region/array tables and stack-offset constants appear. |
| true | false | false | No EH-table generation, lifetime information retained when EH enabled; try/catch/throw survive as partially lowered constructs. |

The latter two rows **still lower the child statements and expressions** and materialize thrown/caught object operations. They emit `enk_lowered_eh_construct`, including `leck_function_prologue`, `leck_function_epilogue`, and `leck_cleanup_state` (`doc/source/lower_il.rst:2884–2910`). The last row is a feasible alternative for a C-like downstream execution IR without EDG's portable EH runtime, but it loses the desired source structure and does not provide complete coroutine lowering.

Couplings are explicit in `src/targ_def.h:5022–5063`: full portable EH forces tables; disabling tables forces `KEEP_OBJECT_LIFETIME_INFO_IN_LOWERED_IL_WHEN_EH_ENABLED=TRUE`. With all lowering disabled, tables are unconditionally disabled at `src/targ_def.h:5355–5357`. The preservation switch is not a promise to retain lifetimes in an EH-disabled lowered build. Full portable try lowering uses setjmp (`doc/source/lower_il.rst:2979–3023`); the chosen profile never invokes it. This restriction concerns compilation of C++ throw/try, not EDG's own internal error-recovery machinery or an explicit user call to setjmp.

Other verified knobs include `LOWER_VARIABLE_LENGTH_ARRAYS`, `LOWER_COMPLEX`, `LOWER_FIXED_POINT`, `LOWER_CLASS_RVALUE_ADJUST` (`src/targ_def.h:519–589`), `LOWER_IFUNC` (`src/targ_def.h:3628–3648`), `LOWER_LVALUE_RETURNING_OPERATIONS`, `LOWER_MICROSOFT_NONCONSTANT_AGGREGATE`, `LOWER_DESIGNATED_INITIALIZERS` (`src/targ_def.h:5212–5240`), and `MINIMAL_INLINING` (`src/host_envir.h:1863–1876`). These do not collectively disable class/constructor/reference lowering while retaining its other work. `DO_C99_IL_LOWERING` is obsolete and must equal `DO_IL_LOWERING` if defined (`src/targ_def.h:508–518`).

## Semantic information available without lowering

| Requirement | Verified upstream representation | Backend contract |
|---|---|---|
| Destructors and initialization | `a_dynamic_init`, including `dik_none` for objects requiring only destruction; selected `destructor`, `lifetime`, reverse `next_in_destruction_list`, initializer temporary lifetime (`src/il_def.h:3946–4050`). | Emit initialization operations and exact semantic references. Preserve evaluated/unevaluated state; a nonnull destructor alone does not imply a cleanup occurs. |
| Lifetime exits | `an_object_lifetime` describes scopes, full expressions, try blocks, labels, parents and ordered destruction lists (`src/il_def.h:17644–17746`). | Preserve lifetime graph, destruction order and relevant jump boundaries. Distinguish automatic obligations from user-controlled `new` lifetimes. |
| Range-for | `stmk_range_based_for` and `a_range_based_for_loop`: optional init statement, iterator, range/begin/end variables with their dynamic initializers, comparison/increment expressions and two scopes (`src/il_def.h:15939–16023`). | Retain a range-for node plus resolved expansion facts; do not redo ADL or overload resolution. Initializations do not necessarily have `stmk_init` wrappers. |
| New/delete | `a_new_delete_supplement`: selected `routine`, placement/alignment/array flags, arguments, dynamic init, exception deallocation action and runtime element count (`src/il_def.h:14677–14761`). | Preserve allocation/deallocation semantics and cleanup. The allocation's size argument is deliberately implicit and must later be supplied from target layout. |
| Coroutines | `a_coroutine_descr`: promise/handle placeholders, parameter copies, initial/final suspension calls, exception handling call, return-object call and selected allocation/deallocation routines (`src/il_def.h:16406–16486`); concrete `enk_await`/`enk_yield` carry resolved await-ready/resume/suspend calls (`src/il_def.h:15676–15689`), whereas dependent prototype operations use `eok_await`/`eok_yield` (`src/il_def.h:14327–14332`). | Preserve coroutine semantics as explicit nodes, not an invented frame-layout/state machine. Downstream realizes suspension, storage, and destruction. |
| Class layout | Class completion calls `do_class_layout` and `set_virtual_function_numbers` before lowering (`src/class_decl.c:33106–33114`); layout entrypoint `src/layout.c:5073`. | Serialize computed size/alignment, fields and base offsets with their validity flags. Record the target profile; incomplete/dependent/managed types must not acquire fabricated native layouts. |
| Virtual dispatch | `an_overriding_virtual_function` records primary/overriding functions, base path and covariant return adjustment (`src/il_def.h:7848–7885`); base offsets and override lists (`src/il_def.h:8134–8244`). | Preserve selected/overridden declarations and adjustment facts. Generated vtable variables and native thunk bodies are not required to exist before lowering. |
| Templates | Prototype instantiations represent dependent templates and are distinct from actual substitutions (`src/host_envir.h:748–764`). | Mark dependent/prototype IL as such; require fully resolved operations in instantiated executable bodies. Never claim all potentially possible instantiations exist. |

The cleanup boundary needs precision. The graph records **destruction obligations**, not already inserted destructor calls on every control-flow edge. Upstream lowering traverses the latest-initialization chain for return/goto, stops at the appropriate lifetime, and creates flags for conditional construction (`doc/source/lower_il.rst:3624–3670`). A downstream consumer still has to realize those obligations on normal and exceptional exits. That is code generation from supplied semantics, not new C++ lookup or overload selection. Array-element partial construction, temporaries, conditional evaluation, and constructor failure must remain expressible; merely storing a scope-level destructor list is insufficient.

Likewise, “fully resolved” cannot mean every entity has a body or static call target: separately compiled external definitions remain references; function-pointer/virtual dispatch remains dynamic; template definitions may be dependent; ABI/runtime operations such as RTTI and coroutine frames remain semantic requests. Actual instantiated expressions must point to the selected semantic declarations, with dependent definitions kept in an explicitly separate category.

## Proposed build configuration

These are proposed explicit settings, not a claim that the entire matrix has already been built. Use an isolated CMake target/configuration; do not inherit the default cpfe backend configuration unchanged (`cmake/macro-conf/default/cpfe.cmakedef:1–5` sets both C generation and lowering).

| Setting | Value | Rationale / dependency |
|---|---|---|
| `BACK_END_IS_C_GEN_BE` | false | Its true value requires lowering (`src/host_envir.h:691–693`). |
| `BACK_END_IS_CP_GEN_BE` | false | This is a third backend, not the source printer. Avoid its unrelated defaults and restrictions. |
| `BACK_END_SHOULD_BE_CALLED` | true | Stock `back_end()` linkage hook (`src/host_envir.h:1243–1258`). |
| `DO_IL_LOWERING` | false | Preserve semantically elaborated C++ IL. |
| `DOING_SOURCE_ANALYSIS` | true | Matches broad source-language acceptance without claiming the stock native backend can implement every extension (`src/host_envir.h:1444–1457`). |
| `IL_SHOULD_BE_WRITTEN_TO_FILE` | false | Consume resident IL; no binary `.cil` interchange (`src/host_envir.h:657–674`). |
| `NEW_CAN_BE_FOLDED_INTO_CTOR` / `DELETE_CAN_BE_FOLDED_INTO_DTOR` / `NEW_AND_DELETE_FOR_ARRAY_CAN_BE_FOLDED_INTO_RUNTIME_ROUTINE` | false | Keep allocation/deallocation targets explicit; parser performs these folds even without IL lowering (`src/expr.c:24839–24913`, `26557–26636`). |
| `ASSIGNMENT_TO_THIS_ALLOWED` | false | Required when constructor/destructor allocation folding is disabled (`src/targ_def.h:3045–3051`); use a separate legacy cfront profile if this extension is required. |
| `MINIMAL_INLINING` | false | It requires lowering (`src/host_envir.h:1874–1876`). |
| `MAINTAIN_NEEDED_FLAGS` | false | Avoid code-emission pruning assumptions. |
| `DEFAULT_REMOVE_UNNEEDED_ENTITIES` | false | Required with needed flags disabled (`src/host_envir.h:1109–1144`). |
| `ONE_INSTANTIATION_PER_OBJECT` | false | Requires needed flags and prelinker metadata (`src/host_envir.h:1147–1176`). |
| `COROUTINE_ENABLING_POSSIBLE` | true | Supported in unlowered IL; stock lowering is incomplete (`src/host_envir.h:3877–3889`). |
| `PROTOTYPE_INSTANTIATIONS_IN_IL` | true | Upstream now forbids false (`src/host_envir.h:748–764`). |
| `IL_WALK_NEEDED` | true | Upstream requires it (`src/host_envir.h:1209–1222`). |
| `GENERATE_SOURCE_SEQUENCE_LISTS` | true | Source correspondence and declaration ordering; traverse actual semantic lists as well. |
| `CLASS_TEMPLATE_INSTANTIATIONS_IN_SOURCE_SEQUENCE_LISTS` / `NONCLASS_TEMPLATE_INSTANTIATIONS_IN_SOURCE_SEQUENCE_LISTS` | false | Putting instances here is deprecated and requires an escape hatch (`src/host_envir.h:1593–1646`). |
| `LOWER_VARIABLE_LENGTH_ARRAYS` / `LOWER_COMPLEX` / `LOWER_FIXED_POINT` / `LOWER_CLASS_RVALUE_ADJUST` / `LOWER_IFUNC` | false | Preserve extension-level operations and satisfy lowering dependencies. |

The legacy cfront profile must retain `ASSIGNMENT_TO_THIS_ALLOWED=TRUE` and both constructor/destructor allocation-folding macros if that accepted extension is in scope. In that profile a null selected `new`/`delete` routine can mean a folded operation, not an unresolved call. Export the class supplement's `assoc_operator_new_routine` / `assoc_operator_delete_routine` and folding flags (`src/il_def.h:9131–9144`), preserving the resolved semantic target without front-end symbol access. Array-runtime folding can remain false independently. This is a representational profile difference, not permission to omit the extension.

With `DO_IL_LOWERING=FALSE`, the exception-lowering macros are not the mechanism controlling semantics; `GENERATE_EH_TABLES` is forced false. Do not enable lowering merely to set EH options. Keep language-level exceptions and RTTI available; user invocation may select upstream's EH-disabled mode, in which case the object must record that mode rather than invent absent exception behavior.

`DOING_SOURCE_ANALYSIS=TRUE` relaxes some ABI-dependent checks. A concrete example is Microsoft casts of pointers to members from virtual bases (`src/targ_def.h:2774–2794`). Therefore a semantic object may be complete as a description while requiring a downstream representation beyond an ordinary Itanium member pointer. The target profile must distinguish semantic support from native ABI interoperability. A separate strict code-generation profile may use `DOING_SOURCE_ANALYSIS=FALSE` and accept its narrower upstream admissibility; that profile cannot stand in for all-extension coverage.

Template policy must be explicit. Ordinary independent-TU compilation should use `INSTANTIATE_TEMPLATES_EVERYWHERE_USED=TRUE`, `LINKER_CAN_DISCARD_DUPLICATE_DEFINITIONS=TRUE`, `DEFAULT_INSTANTIATION_MODE=tim_used`, and `AUTOMATIC_TEMPLATE_INSTANTIATION=FALSE`, **with duplicates recorded as a future linker responsibility**. The exporter and reader do not implement linking or merge these definitions in the current phases; the setting only tells EDG to materialize needed definitions in each independent TU. These dependencies and defaults are in `src/host_envir.h:860–961`. This does not instantiate every unused template or override explicit instantiation declarations. Retain identities and definition availability.

Legacy exported templates need a compatibility profile: upstream says the everywhere-used/no-prelinker scheme cannot implement exported templates (`src/host_envir.h:880–885`). Retain automatic-instantiation/definition-discovery machinery there and record the selected mode. Secondary-TU IL is copied into the primary before the backend (`src/fe_wrapup.c:695–745`). The operational prelinker/driver workflow for this profile remains to be exercised; one backend invocation must not be advertised as complete whole-program legacy-export support.

Do not enable `ALL_TEMPLATE_INFO_IN_IL` indiscriminately merely to obtain used instances. It preserves prototype function bodies, and affects default prototype-deferral policy (`src/host_envir.h:727–790`), which upstream says can change the set of error-free programs. A source-template archive profile can enable it deliberately; executable semantic coverage relies on actual needed instances. Similarly, `MANGLE_ALL_NAMES=TRUE` is optional if external-name strings are required: unlowered mangling is supported (`src/host_envir.h:1778–1831`; `src/fe_wrapup.c:359–366`). Preserve both spelling and mangled encoding and never use a mangled name as the only object identity.

## Concrete language and provenance profiles

All profiles use the unlowered backend settings above. The following are build configurations plus runtime modes, not simultaneously selectable dialect promises. The feature manifest records resolved macro values and command-line settings. Shared source capabilities include `C99_IL_EXTENSIONS_SUPPORTED=TRUE`, `CPP11_IL_EXTENSIONS_SUPPORTED=TRUE`, `GNU_EXTENSIONS_ALLOWED=TRUE`, `MICROSOFT_EXTENSIONS_ALLOWED=TRUE`, `COROUTINE_ENABLING_POSSIBLE=TRUE`, and `REFLECTION_ENABLING_POSSIBLE=TRUE`; retain other enabled upstream families rather than narrowing the full-featured configuration (`src/defines.h:3350–3364`, `3426–3428`, `3462–3464`, `3690–3692`).

| Profile | Concrete distinctions | Acceptance boundary |
|---|---|---|
| Independent native C++ | `COMPILE_MULTIPLE_TRANSLATION_UNITS=FALSE`, `COMPILE_MULTIPLE_SOURCE_FILES=FALSE`; instantiate-used settings above; allocation folding and assignment-to-this false. | Exercise `--c++03`, `--c++11`, `--c++14`, `--c++17`, `--c++20`, `--c++23`, `--c++26`, with their upstream accepted feature sets. Latest mode is selected explicitly, not inferred from compiler version. |
| GNU native | Same build; `--g++` plus an explicit supported GNU compatibility version and C++ standard. | GNU-specific nodes remain typed semantics; no ifunc/VLA/complex lowering. Record runtime target/compatibility settings. |
| Microsoft native | Same unlowered build; `--microsoft` and explicit Microsoft compatibility version and supported C++ standard; select Microsoft member-pointer sizing if required by target profile. | Retain MS SEH, properties, calling conventions, member-pointer and layout facts; do not claim Itanium/MS native binary equivalence. |
| Managed Microsoft | `CPPCLI_ENABLING_POSSIBLE=TRUE`, `CPPCX_ENABLING_POSSIBLE=TRUE`; `--c++cli` or `--c++cx` separately, with their accepted dialect constraints. | Native Windows metadata importer or upstream portable-assembly reader profile with available metadata. No core metadata emulation. |
| Legacy cfront | Assignment-to-this and both ctor/dtor allocation folding flags true; `--cfront_2.1` or `--cfront_3.0`. | Preserve class-associated allocation routines and folded-operation state rather than treating null direct targets as unresolved. |
| Legacy exported templates | `EXPORT_ENABLING_POSSIBLE=TRUE`, `AUTOMATIC_TEMPLATE_INSTANTIATION=TRUE`, `INSTANTIATE_TEMPLATES_EVERYWHERE_USED=FALSE`, compatible ABI version >=232; retain upstream prelinker/definition discovery. | Secondary definitions imported by EDG are part of the primary semantic artifact with origin; current reader does no inter-object linking. Workflow validation remains required. |

Standard mode registration is at `src/cmd_line.c:1543–1556`; the Microsoft/managed options are at `569–661`, GNU mode/version at `1285–1300`, and cfront at `291–296`. C++26 requires nonclass prototype parsing; upstream rejects `--no_parse_templates` in that mode (`src/cmd_line.c:12388–12396`). Do not relax that requirement to retain a more permissive legacy-template policy.

The ordinary provenance profile explicitly enables `EXTRA_SOURCE_POSITIONS_IN_IL`, `RECORD_MACROS_IN_IL`, `FULLY_RESOLVED_MACRO_POSITIONS`, `RECORD_MACRO_INVOCATIONS`, `MACRO_INVOCATION_TREE_IN_IL`, and `RECORD_MACRO_ARGS`. The macro invocation tree conflicts specifically with `COMPILE_MULTIPLE_TRANSLATION_UNITS=TRUE` (`src/host_envir.h:387–390`), so the independent-object profiles set that macro false even if upstream's broad configuration defaults it true. See the API/provenance design for the six flags' dependency details.

Legacy exported-template secondary TUs are a distinct mechanism and can occur even with `COMPILE_MULTIPLE_TRANSLATION_UNITS=FALSE` (`src/trans_unit.c:752–770`). Therefore that compile-time incompatibility alone neither proves nor disproves correct macro-context retention after secondary-IL copying. Until an acceptance probe verifies that provenance path, use a conservative exported-template profile with `MACRO_INVOCATION_TREE_IN_IL=FALSE`, `RECORD_MACRO_INVOCATIONS=FALSE`, and `RECORD_MACRO_ARGS=FALSE`; keep definition records, original coordinates and extra positions enabled, record invocation-tree unavailability, and retain all semantic IL. Enabling the full tree for this profile is a validation-gated retention improvement, not a semantic-core patch. An explicit merged-input profile, if needed for an upstream extension workflow, uses the same reduced provenance configuration and records EDG's input ownership; it is not cross-object linking in the new library.

Source archival is optional and external to `.roslynobj`: store attachment identity, encoding, digest and acquisition provenance as scalar fields/relations. No source-byte BLOB or encoded byte dump is introduced into the semantic object. Any alternative in-database exact code-unit representation must use normalized scalar rows under the relational contract.

## Backend integration without core EDG changes

The stable verified entrypoint is `void back_end(void)` in the EDG namespace. `src/cfe.c:125–180` invokes it after TU processing and `fe_wrapup()`, suppresses it on diagnostics containing errors, and then calls `fe_wrapup_part_2()`. Implement this symbol in new `roslyn_gen_be.c`; both stock backend flags remain false, so neither stock generator defines it. Register/link the new translation unit and SQLite through build configuration only. All upstream `.c` sources compile as C++ (`src/CMakeLists.txt:169–174`; `src/cmake/cpfe/CMakeLists.txt:12–13`). SQLite's amalgamation must be placed in its own C-compatible target or linked as an external library; do not accidentally subject it to EDG's forced `-x c++` directory options. No EDG runtime library is needed merely to serialize IL; disable the optional EDG library build for this target, whose setup otherwise requires `EDG_BASE` (`CMakeLists.txt:99–114`).

A separate `cpfe-roslyn` target can reuse the core source set (`src/CMakeLists.txt:205–216`) with its own macro configuration, analogous to existing target separation (`src/CMakeLists.txt:251–256`; `src/cmake/cpfe/CMakeLists.txt:7–17`). Compile all source files for that target with a coherent macro set; do not reuse incompatible object files from cpfe/cpfe-cp because IL structures are macro-dependent. SQLite output has its own versioned schema and must never be an EDG memory image.

There is no verified generic per-function backend callback. `finish_function_body_processing` is static and performs lowering, orphan collection and needed-flag bookkeeping (`src/scope_stk.c:8912–9027`). Its occurrence is not an integration hook and does not authorize inserting a core call. Whole-TU resident IL avoids the need for one.

Memory-lifetime rules are mandatory:

1. `fe_wrapup` frees **front-end-only storage before backend entry** when IL stays in memory (`src/fe_wrapup.c:842–854`). Do not dereference symbol pointers such as `source_corresp.assoc_info`, parser scopes, or any field documented front-end-only. In particular, do not invoke overload/layout/instantiation routines from the backend to fill gaps.
2. File/routine IL regions remain until post-backend cleanup (`src/fe_wrapup.c:866–885`). `scope_for_routine` and `mem_region_for_routine` are the reference pattern (`src/c_gen_be.c:10360–10382`). Assign persistent database identities while pointers are valid; serialize references as IDs, never addresses.
3. Traverse orphan local types/static variables as well as declaration lists. Stock function finalization collects orphan lists (`src/scope_stk.c:8972–8988`); a routine-only traversal misses reachable file-region entities.
4. If a future memory-scalable profile uses `IL_SHOULD_BE_WRITTEN_TO_FILE=TRUE`, the backend must read the file-scope image and load routine regions before traversal; C generator demonstrates reads and bounded region release (`src/c_gen_be.c:10522–10623`, `12212–12233`). Region pointer reuse invalidates a naïve cross-region address-to-ID cache. This is an alternative profile, not the initial default.
5. Never retain an EDG pointer after `back_end` returns. Callable/multiple-compilation modes reinitialize state; each object generation needs a fresh identity map and SQLite connection.

Stock `-o/--output` is **not** a free custom-backend output-path channel. `proc_command_line` stores it in local `ofile_name` (`src/cmd_line.c:11030–11033`), consumes it for preprocessing or `.cil` (`12989–13000`), and errors if unused (`13047–13052`). With no core edits, derive `<input>.roslynobj` or let the new backend read an explicit `ROSLYNOBJ_OUTPUT` environment variable. An external wrapper may translate its own `-o` into that variable. Claiming existing cpfe `-o foo.roslynobj` works in the in-memory profile would be incorrect. `--front_end` and `--write_unlowered_il` suppress the backend (`src/cmd_line.c:10663–10670`, `10703–10715`); use the configured target, not those switches, to request semantic output.

Build-profile resource policy: start with one-TU CLI execution. Open a temporary SQLite file inside `back_end`, run a transaction, validate references, commit, close and atomically replace the destination only after success. On serialization failure, rollback/close before calling any EDG error routine that can escape the current call. There is no generic custom-backend abnormal-cleanup callback in `fe_cleanup`; it explicitly calls only CP-generator cleanup under that backend flag (`src/fe_wrapup.c:890–925`). For an embeddable callable profile, a host wrapper must own an explicit cleanup function exposed by the new backend and call it after EDG returns, including fatal return paths. Alternatively a narrowly permitted backend-registration hook would need separate implementation review. Do not rely on C++ stack unwinding: upstream builds with `-fno-exceptions` (`src/CMakeLists.txt:159–167`).

## Coverage claim and required validation

The backend should support every construct **the selected pinned upstream build and invocation accepts**, including all available C++ versions and Microsoft/GNU modes. That is not a claim that upstream implements every feature of each published standard, that all extension modes coexist in one invocation, or that one ABI layout describes every target. Preserve feature/configuration provenance in every object. GNU vectors, complex numbers, statement expressions, computed gotos, assembly, attributes, Microsoft SEH, managed handles/properties and other conditional kinds require their own semantic payloads; turning off lowering does not excuse an incomplete visitor.

Microsoft pointer-to-member sizing explicitly cannot coexist with stock lowering (`src/targ_def.h:2767–2771`), further supporting the unlowered design. C++/CLI plus lowering is forbidden except a test escape that suppresses both lowering and backend when CLI/CX is enabled (`src/host_envir.h:694–705`). The unlowered backend avoids that coupling, but managed metadata support still needs an appropriate host/profile: MSVC builds add `ms_metadata.cpp` and link `mscoree` (`src/CMakeLists.txt:239–247`), while non-Windows builds can select upstream portable-assembly reading (`src/defines.h:3643–3646`; `src/host_envir.c:6374–6376`). Actual managed metadata import and legacy exported-template workflows are profile-specific validation gates, not silently declared solved by native C++ tests.

Before implementation is called complete, run an exhaustive compile-time kind/field inventory for each configured IL shape, then behavioral export probes spanning actual instantiation, overloads, temporary lifetime extension, return/goto/break/continue cleanups, exceptions, partial-array construction, aligned/placement/sized delete, range-for ADL, coroutine suspension/destruction, inheritance/virtual/covariant dispatch, modules, and each enabled extension family. Verify no unexpected dependent nodes in concrete executable bodies and no unsupported-kind fallback. Validate class-layout facts against upstream-computed values and preserve unresolved/external status where appropriate. The design verifies that the data structures and integration point exist; it does not substitute for these implementation acceptance tests.
