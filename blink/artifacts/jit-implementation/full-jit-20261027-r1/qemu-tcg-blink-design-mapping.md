# QEMU TCG → Blink implementation mapping

Reference: QEMU commit `29b1dc631d6ac6bfc39464e0be8bf4cad556a591`, resolved from upstream HEAD on 2026-10-28. Reading only; independently authored implementation, no QEMU code or dependency enters Blink. Exact reference hashes: `qemu-tcg-source-reference-pins.json`.

| QEMU source behavior | Required Blink correction |
|---|---|
| Per-CPU jump cache misses use the shared TB hash table; collisions do not free translations. | Nonowning worker jump hints backed by the owner-wide exact retained index; compilation rechecks the index under the translation gate. |
| TB descriptors and code use aligned pointer advancement in code regions; translation pools reset and reuse normal chunks. | Append descriptors, payload and packed code in bounded reusable arenas. Reuse compiler scratch. Remove individual page-run allocation and buddy turnover; count alignment and page slack separately. Mutable descriptors remain RW separately from RX code. |
| User-mode TCG uses one region; exhaustion either flushes in a serial context or queues an exclusive flush. Flush clears jump caches, the shared index and region state. | Remove protected/probation/per-body eviction. Exhaustion requests an owner-wide flush; reset only after native epochs, managed leases and drafts have drained, then retry the same approved guest issue. Helpers hold copied plans across that boundary. |
| Invalidation removes affected TBs from lookup and reverse jump lists; user-mode tracks guest ranges, system mode physical page lists. | Record checked fetch provenance, invalidate affected mappings/physical aliases before writes, unlink incoming and outgoing edges. Reads retain lifetime protection but must not revoke code as writes. Invalidated arena bytes wait for the bulk flush. |
| Native helpers follow the host C ABI; TB host-PC metadata supports state restoration. | Our generated leaf returns to managed code before typed managed helpers: copying the exact predecoded plan under a lease, ending the native epoch, and materializing precise IP/oplen allows GC and managed JumpBuffer unwinding. No general opcode dispatcher. Linux guest faults/signals and recursive handlers retain precise per-instruction state. |

Divergences: QEMU supports writable/executable aliases on POSIX and its current Windows buffer path uses RWX. Blink keeps single-mapping RW→RX W^X on both hosts. Packing another body into a shared tail page therefore closes native admission and requires quiescence while that page is RW, then seals RX before publication. Mutable authenticated data links avoid patching executable pages; reverse unlinking and epoch protection still apply. CoreCLR and NativeAOT share this explicit leaf/managed-helper boundary; no claim of asynchronous generated-frame stackwalk support. Real Windows remains UNVERIFIED. Precise instruction budget, cancellation, attention, code-generation and state guards remain, but repeated native scaffolding is shared within a block rather than emitted in full at every site.

Measured pre-correction baseline: c8 CoreCLR service compiled 9,003,426 TBs, emitted 27,355,989,297 cumulative bytes, and took 3,421.88 seconds. Instrumented 100m-issued prefixes at 128/256/512 MiB found about 52.5k distinct keys. The 512 MiB prefix had 52,449 publications, one content retirement, zero capacity retirements, 162,521,550 cumulative emitted bytes and 253 MiB code-region reservations. Approximately 98 MiB separates emitted bytes from code reservations; that combines whole-page rounding and region tail slack, not an exact separate measurement. Payload and descriptor occupancy were not exported. The larger prefix was slower under instrumentation, so these runs do not establish a winning size or performance result. New counters must distinguish current/peak useful code, aligned code, page/region slack, payload, descriptors/index, fixed charge, cumulative emission, publications and flushes. Historical 104 B was heap allocation per successful semantic binding/miss, not per executed instruction. Zero semantic-window allocation was never globally allocation-free.

Implementation status: the current frozen consumer is tb3c18, including arenas, whole flush, indexed physical authority, owner-shared scaffold,512 policy, owner compiler pool and designated publication admission. Linux CoreCLR and NativeAOT contracts pass142811 checks each; c17 completed44/44 matrix cells, and c18's fresh matrix remains active. R47/R48/R52 source reviews cover publication progress, scratch sizing and paged physical-write barriers. Current services/performance remain pending; real Windows is UNVERIFIED. R32's fixed-charge finding is corrected and R35 source-clear. No completion claim.

Additional divergences: Blink grows code mappings and separate mutable data arenas within one charged quota rather than preallocating QEMU's user buffer. Its serialized shared index uses bounded arena-backed hash buckets rather than QHT. Authority-only revocation preserves a nonlive key for exact-byte revalidation; content invalidation removes it. Worker hint count remains configurable (current default 256 versus QEMU's 4096); neither hint collision owns or evicts a body. Capacity retirement now means bodies discarded by whole-buffer flush, not individual victim selection. Lookup metrics now separate actual worker-hint misses from explicit shared-index queries and resident-token resumes; older figures mixed these categories.

C9 shares the body-independent native prologue/guards/issue/link/exit code once per owner (one RX mapping), following the common-code allocation principle in TCG. Compact bodies retain their actual native operations, helper staging, resume labels and absolute JMP continuations. The shared code remains rooted across arena flushes and is released after quiescent store disposal; its emitted/reserved bytes are charged separately from TB emission. All exits materialize actual guest IP. R41 source review and current CoreCLR contracts passed; broader current-source qualification is active.


The current candidate supersedes c9's arbitrary32 policy. Primary block-policy reference is QEMU commit `c81ee5d570014d83d2edf9ccc0f8bfa2b7d13e63`, retained as reference only in the block-policy pin receipt. QEMU uses normal512 instructions, target/control/page endings, bounded generation and a halved count retry for oversized output ([header](https://github.com/qemu/qemu/blob/c81ee5d570014d83d2edf9ccc0f8bfa2b7d13e63/include/exec/translation-block.h), [generation](https://github.com/qemu/qemu/blob/c81ee5d570014d83d2edf9ccc0f8bfa2b7d13e63/accel/tcg/translate-all.c), [translator loop](https://github.com/qemu/qemu/blob/c81ee5d570014d83d2edf9ccc0f8bfa2b7d13e63/accel/tcg/translator.c), [x86 boundary policy](https://github.com/qemu/qemu/blob/c81ee5d570014d83d2edf9ccc0f8bfa2b7d13e63/target/i386/tcg/translate.c)).

Blink's new implementation requests512 normally and1 for its precise recursive signal actor; request count participates in the retained key. It decodes only already checked bytes of the starting page, stops at decoded control/state changes, and preserves a demand-fetched straddling first instruction as one body. The backend uses a64KiB staging envelope because it fits the smallest code region and bounds reusable compiler resources; this is a Blink resource policy, not QEMU's64KiB unwind constraint. Oversized emission halves a prefix before publication. Compiler plans/IR/code occupy preallocated owner scratch slots, including bounded recursion slots, rather than a large per-call stack or fresh managed arrays.

Block size and scheduling are distinct. Normal frame cap0 means no fixed instruction quantum; eligible native backedges/links continue until an actual budget, stop, attention, authority or helper exit. Signal actors and untrusted backing retain explicit cap1. Cheap per-instruction issue/poll checks currently remain a deliberate precision divergence from QEMU's native helper/state-restoration design. Native execution releases the authority gate while retaining a managed body lease, store-wide native epoch and passive physical pin. Writers advance the polled epoch and drain native enrollment before memory effects; packed W^X publication requests the same quiescence when needed. Native helpers still RET before managed GC/exception/guest JumpBuffer boundaries. Windows/SysV leaf ABI and owner-common RX lifetime remain explicit; real Windows execution and asynchronous native unwind remain unqualified. The preserved c9 receipts do not qualify these changes; current evidence is pinned separately above.
