# Direct Zig default milestone, 2026-11-06

This is the historical 0.1.0 milestone at `51b1be1f59bb351806e724ed58b712f0bdb8e091`.
The current canonical product is the qualified [vt-1.0.0 upgrade](VT-1.0.0.md).

The ordinary product is the working managed C# libghostty translated directly
from pinned Zig by DotCC. The default reference chain is
`ManagedConsumer` → `Managed.GhosttyVt` →
`generated/TranslatedGhosttyVt/TranslatedGhosttyVt.csproj`.
The corresponding raw project is
`generated/TranslatedGhosttyVt.Raw/TranslatedGhosttyVt.csproj`.
Both delivered source trees are byte-identical to the previously qualified direct
publication. Normal regeneration selects the `direct` profile, including the real
Zig module graph and the authored boundary; it does not translate a C engine.

This milestone includes the compiler/runtime implementation, source compatibility
patches, regressions, delivery scripts and canonical generated sources. The source
pin is Ghostty `93967b7f9478e94dcbb42125c8a90f34feb40d75`, with Zig 0.17.0,
scalar Linux x64 LP64, Lib output, fast optimization and source standard-library
types. Managed function pointers and required host services remain real product
dependencies; external native-library delivery is outside this milestone.

The delivered product passed owning-consumer, 24-case differential and allocation
checks in raw/processed × JIT/NativeAOT rows. Default publication was then checked
with no `TranslatedProject` override: the ordinary solution builds with zero
warnings/errors, and the consumer passes terminal output/style, split UTF-8,
alternate screens, resize/reset, concurrent isolation and disposal. Raw and
processed PE/RVA audits pass: 92 selected entry bodies, 61 immutable getters with
zero warmed allocations, and storage helpers bounded by two parameters (observed
maximum one). The isolated compiler source included in this commit is rebuilt and
checked against the actual engine and focused regressions before committing.

Full upstream managed qualification is **pending**. Existing raw/JIT acceptance
covers 287 disjoint upstream cases (58 render and 229 core); it does not represent
the complete 2,622-case managed matrix or its other execution rows. The original
and projected full native controls passed before compatibility patch 0015; that
patch has focused C/Zig native validation and a successful private engine/consumer
integration. The final full source-set refresh is still required. Canonical
published bytes retain patches 0001–0014 and were not regenerated by later private
qualification work. The committed regeneration manifest additionally includes
validated patch 0015; no claim of byte-identical regeneration is made.

Unfinished edits are deliberately excluded: loop-`else` handling and its controls,
keys-caller diagnostics/controls, the latest aligned-slice/composite type metadata
changes, unresolved optional-vector/forward-null controls, and unapplied patch
0016. They remain working-tree campaign work, outside this accepted milestone.
Accepted C evidence and source products remain available locally under
`generated/c-route/`; their accepted implementation is retained at commit
`3592b42929380f9cbd3209d8729f600629e85999`. No C fallback or unrelated Blink work is
included in this milestone.

Recheck the ordinary default from the repository root without a project override:

```sh
dotnet build libghostty/ManagedConsumer.slnx -c Release \
  -p:PublishAot=false -p:UseArtifactsOutput=true \
  -p:ArtifactsPath=/mnt/storage/dotcc-libghostty-disposable/default-check

dotnet /mnt/storage/dotcc-libghostty-disposable/default-check/bin/ManagedConsumer/release/GhosttyVt.Consumer.dll
```

Normal delivery commands are `libghostty/scripts/translate.sh`, `build.sh`,
`test.sh`, and `verify.sh`. Their default direct verification is a consumer smoke
check; full upstream acceptance remains a separate requirement. Explicit
`--profile scalar` retains the legacy C preparation route. Disposable toolchains,
builds, caches and scratch products stay under
`/mnt/storage/dotcc-libghostty-disposable`.

Compact commit validation and source/publication receipts are retained under
`artifacts/direct-default-milestone/`; historical detailed campaign receipts
remain under `artifacts/direct-resume-20261104/`. Neither location grants full
campaign acceptance.
