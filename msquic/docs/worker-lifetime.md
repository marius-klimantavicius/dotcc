# Worker and PAL lifetime contract

The P3 platform implementation now supplies the BCL services below in [MsQuicHost.Platform.cs](../src/BclHost/MsQuicHost.Platform.cs) and [MsQuicHost.Queue.cs](../src/BclHost/MsQuicHost.Queue.cs). The raw/optimized × JIT/NativeAOT service matrix passes against the frozen P2 generated closure, including real translated worker threads. This is a platform-services gate, not a claim that the complete QUIC transport works. The implementation retains the pinned `platform_worker.c` scheduler and its classic single-consumer completion path. External execution queues, io_uring batch completions and OS affinity remain outside the [first API profile](api-profile.md).

## What the upstream worker requires

Each worker embeds its thread token, queue and three long-lived control SQEs: shutdown, wake and update-poll. It also owns the execution-context lock/lists and dynamic-pool list. The pool owns the contiguous worker allocation and its rundown reference. These C allocations remain stable until all references and threads have drained. [Worker fields, `platform_worker.c:18`](../ref/msquic-80a065112426bce68c1da42d026478d3e40fd45e/src/platform/platform_worker.c#L18); [pool fields, line 107](../ref/msquic-80a065112426bce68c1da42d026478d3e40fd45e/src/platform/platform_worker.c#L107).

Initialization creates the EC lock, initializes the queue, registers shutdown/wake/update-poll SQEs, and only then creates the thread. Per-resource initialized bits drive partial-failure cleanup. The local `ThreadConfig` is reused across workers, and its `Context` is changed before each create: the host must copy its callback, context, flags, processor and name before returning. A thread may begin during `CxPlatThreadCreate`; all input state and its managed ownership must already be published. [Initialization, line 164](../ref/msquic-80a065112426bce68c1da42d026478d3e40fd45e/src/platform/platform_worker.c#L164); [stack thread config and creation loop, line 321](../ref/msquic-80a065112426bce68c1da42d026478d3e40fd45e/src/platform/platform_worker.c#L321).

The C worker controls when execution contexts run, their deadlines, and when the queue waits. The host supplies a dedicated BCL thread and queue primitives; it must not add a second scheduler that runs EC callbacks on ThreadPool continuations. A context callback returning false removes the context; returning true retains it. The loop consumes the `Ready` bit atomically and computes the next wait from the core deadline. [Context execution, line 596](../ref/msquic-80a065112426bce68c1da42d026478d3e40fd45e/src/platform/platform_worker.c#L596); [worker loop, line 784](../ref/msquic-80a065112426bce68c1da42d026478d3e40fd45e/src/platform/platform_worker.c#L784).

Two upstream coalescing rules are significant:

- Adding an execution context publishes it under `ECLock` and enqueues update-poll only when the pending list was previously empty. The completion drains the whole pending list. One CQE is not one context. [Add, line 531](../ref/msquic-80a065112426bce68c1da42d026478d3e40fd45e/src/platform/platform_worker.c#L531); [drain, line 575](../ref/msquic-80a065112426bce68c1da42d026478d3e40fd45e/src/platform/platform_worker.c#L575).
- Waking atomically sets `Worker->Running` and only enqueues when the previous value was false. Before sleeping, the worker clears this bit and runs ECs again if it had been set. Preserve this race-handling protocol; a host signal must survive the interval before the consumer actually waits. [Wake, line 555](../ref/msquic-80a065112426bce68c1da42d026478d3e40fd45e/src/platform/platform_worker.c#L555); [second pass, line 808](../ref/msquic-80a065112426bce68c1da42d026478d3e40fd45e/src/platform/platform_worker.c#L808).

Neither producer checks `StoppingThread`. The owning layer must quiesce producers through the upstream lifetime protocol; queue cleanup cannot repair a stale C pointer. Pool rundown waits for reference holders, but `CxPlatRefIncrementNonZero` can still add a reference while the count remains nonzero. Therefore “begin shutdown” must prevent new application work before relying on rundown to finish. [Pool delete/addref/release, line 441](../ref/msquic-80a065112426bce68c1da42d026478d3e40fd45e/src/platform/platform_worker.c#L441); [nonzero increment, `platform_posix.c:357`](../ref/msquic-80a065112426bce68c1da42d026478d3e40fd45e/src/platform/platform_posix.c#L357); [rundown wait, line 456](../ref/msquic-80a065112426bce68c1da42d026478d3e40fd45e/src/platform/platform_posix.c#L456).

## Managed ownership

The following records describe managed state behind existing ABI tokens; they do not change generated C layouts. Strong references returned by the typed registry retain managed record lifetime during an operation. Resource-specific gates and upstream producer quiescence govern concurrent disposal; the registry does not make stale C memory access valid.

| Managed owner | Owned state | Lifetime and borrowed data |
| --- | --- | --- |
| Host instance | Token registry, allocation registry, fatal-state latch, static callback roots | Survives all core workers, socket/TLS completions and registered handles; released after system unload |
| Token registry | Nonzero monotonically assigned `uintptr_t` IDs to strongly rooted typed records | Lookup returns a strong typed record reference; no token reuse, checked host/type ownership, and fatal exhaustion rather than wrapping |
| Queue record | Monitor gate, Open/Closing/Closed state, intrusive ready list, SQE registrations, consumer identity, one outstanding batch, wait/deadline state | Owns SQE records until unregister and batch release; does not own their containing C workers |
| SQE record | Queue owner, borrowed C SQE address, registered callback identity, Open/Closing/Closed state, Pending bit, queue links, InFlight count | Allocated/linked at successful initialization; no allocation on enqueue; C owner keeps SQE and Completion stable until cleanup returns |
| Batch record | Preallocated array of strong SQE-record references plus exact count and consumer identity | Filled by dequeue and cleared by matching return; never stores the caller's stack `CXPLAT_CQE*` buffer |
| Thread record | BCL Thread, copied typed function pointer/context/name/flags/ideal processor, start/end/fault state, logical thread ID | Rooted before starting; C context remains borrowed until callback exits; wait joins, delete removes token only after termination |
| Lock/event records | Private synchronization gate, owner/waiter or signaled/reset-mode state, lifetime leases | Uninitialization follows quiescence; no pending waiter is silently converted to success |
| Allocation record | Pinned byte backing, base address, aligned user address, requested byte count and tag | MsQuic allocator-domain registry retains backing until matching CxPlatFree; no movable managed object reference goes into C fields |

Use the managed-token registry rather than treating an ID as a managed object address. Registry publication/removal never holds its lock while acquiring a resource lock, waiting, joining or calling translated code. Resource operations retain the returned managed reference after registry lookup. This prevents GC movement and handle-reuse races without placing managed references in C memory. It does not legalize callers using a C object after its owner freed it.

The overlay fixes queue/token widths: queue/event/lock handles are pointer-sized, `CXPLAT_CQE` contains the originating `CXPLAT_SQE*`, and `CXPLAT_SQE` contains Handle followed by the typed Completion pointer. Keep those ABI fields unchanged. [Host queue ABI, `quic_platform_posix.h:805`](../config/managed-host/inc/quic_platform_posix.h#L805); [thread config, line 833](../config/managed-host/inc/quic_platform_posix.h#L833).

## Queue operations and counting

The initial queue contract is **multiple producers, one dedicated consumer, one outstanding batch**. Classic control SQEs carry notifications, not counts of application work. Native epoll registration uses edge-triggered readiness plus an eventfd, and returns readiness records rather than an eventfd count to the worker. The selected managed coalescing behavior below is a host policy justified by the control callbacks; it is not a claim of byte-for-byte epoll behavior. [Native enqueue/dequeue, `quic_platform_posix.h:1380`](../ref/msquic-80a065112426bce68c1da42d026478d3e40fd45e/src/inc/quic_platform_posix.h#L1380); [epoll SQE initialization, line 1419](../ref/msquic-80a065112426bce68c1da42d026478d3e40fd45e/src/inc/quic_platform_posix.h#L1419).

`CxPlatEventQInitialize` allocates the queue record and initial batch capacity before publishing its token. The selected worker requests at most 16 CQEs. Queue registration grows any required management capacity before it succeeds; normal dequeue/enqueue/return do not allocate. If future callers request larger batches, return up to the preallocated capacity while honoring the caller's Count, or extend capacity at registration; never overrun the caller's array.

`CxPlatSqeInitialize` allocates its host record and intrusive queue node, records the queue association, then writes the C Completion and nonzero Handle before returning true. Failure leaves no registration or usable token and returns false. These are control notifications, not a place to store socket payloads. A future datapath operation needs its own exact completion and packet-buffer lifetime contract.

`CxPlatEventQEnqueue` takes the queue gate, validates the live registration and owner, and performs these transitions:

| Current SQE state | Enqueue effect |
| --- | --- |
| Open, not pending, not in flight | Append its preallocated ready node once; set Pending; signal the consumer |
| Open, already pending | Coalesce into that pending notification; still return true |
| Open, in flight, not pending | Append a new pending notification for the next batch; do not mutate the current CQE |
| Closing/closed or wrong queue | Return false; no notification or callback |

Enqueue releases the gate after publishing readiness. Signals alone are insufficient: dequeue checks the queue predicate under the same gate before waiting. Enqueues racing a dequeue therefore either enter its batch or remain pending for a later batch. Pending and InFlight are independent: returning a batch must not clear a new Pending bit. At most one ready node per SQE exists; distinct transitions use FIFO queue order, while multiple requests for the same already-pending control SQE coalesce.

A successful initialized control enqueue must be allocation-free and lossless. In particular, `CxPlatWorkerPoolDestroyWorker` ignores the shutdown enqueue's boolean result and immediately joins. Returning false for a transient capacity/allocation problem would hang destruction. Resource exhaustion belongs in queue/SQE/thread initialization, before their success bits are set. Closing rejection is only valid once producer admission has stopped; normal worker teardown keeps the queue open until the shutdown completion and join finish. [Shutdown enqueue, `platform_worker.c:235`](../ref/msquic-80a065112426bce68c1da42d026478d3e40fd45e/src/platform/platform_worker.c#L235).

`CxPlatEventQDequeue` waits for pending entries according to WaitTime, removes up to `min(Count, batch capacity)` nodes under the gate, clears each Pending bit, increments each InFlight lease, copies only its C SQE pointer to the caller's CQE array, and records the strong managed batch references. It returns a count in `[0, Count]`. It never invokes Completion. A producer cannot append a second occurrence while this extraction holds the gate, so the same SQE appears at most once per batch. For the selected caller, Count is 16 and `CxPlatProcessEvents` owns the stack array. [Dequeue and stack CQEs, line 732](../ref/msquic-80a065112426bce68c1da42d026478d3e40fd45e/src/platform/platform_worker.c#L732).

The worker invokes every returned Completion outside all host queue/registry locks. Even when shutdown appears in the middle of the batch, later entries in that same batch are still invoked. `ShutdownCompletion` sets `StoppedThread`; it does not break the current callback loop. The worker then calls `CxPlatEventQReturn` with the **original** count and only exits at the next loop condition. [Shutdown completion, line 128](../ref/msquic-80a065112426bce68c1da42d026478d3e40fd45e/src/platform/platform_worker.c#L128); [dispatch and return, line 760](../ref/msquic-80a065112426bce68c1da42d026478d3e40fd45e/src/platform/platform_worker.c#L760).

`CxPlatEventQReturn` requires the current consumer and exact outstanding count, decrements all batch InFlight leases, clears the batch references, and wakes cleanup waiters. It must not dereference the caller's expired CQE array and must not invoke or replay callbacks. A zero dequeue creates no outstanding batch; the worker does not call Return for it. A second dequeue before return, wrong count, concurrent consumers or unmatched return is a contract failure, never a fabricated successful drain. Tracking the batch is a deliberate stronger managed lifetime contract even though native epoll's Return is a no-op.

## Waits, events and atomics

Queue WaitTime is milliseconds: zero polls, `UINT32_MAX` waits indefinitely, all other values are finite unsigned durations. Convert finite waits through an absolute monotonic deadline and bounded wait chunks; do not cast a large `uint32_t` to a negative BCL timeout, restart the full timeout after each pulse, or use UTC wall time for worker deadlines. A timeout/spurious wake with no ready nodes returns zero after the deadline. A normal initialized queue cannot be closed under its active worker; returning zero forever on a prematurely closed queue would make the worker spin rather than shut it down. [Native timeout convention, `quic_platform_posix.h:1395`](../ref/msquic-80a065112426bce68c1da42d026478d3e40fd45e/src/inc/quic_platform_posix.h#L1395); [core deadline conversion, `platform_worker.c:640`](../ref/msquic-80a065112426bce68c1da42d026478d3e40fd45e/src/platform/platform_worker.c#L640).

Events retain a persistent Signaled predicate and ManualReset/AutoReset mode. Set-before-wait must succeed; repeated Set on an already-signaled event coalesces. An auto-reset event releases one successful waiter and consumes the signal under the gate. A manual-reset event releases all eligible waiters and stays signaled until Reset. Wait loops recheck the predicate, including after spurious pulses, and timed waits use a monotonic deadline. Event uninitialization requires all waiters and concurrent setters to have left. The upstream rundown event is auto-reset and initially nonsignaled; replacing it with a counting semaphore without equivalent predicate/reset behavior changes the contract. [Event initialization, `quic_platform_posix.h:877`](../ref/msquic-80a065112426bce68c1da42d026478d3e40fd45e/src/inc/quic_platform_posix.h#L877); [Set and wait, line 920](../ref/msquic-80a065112426bce68c1da42d026478d3e40fd45e/src/inc/quic_platform_posix.h#L920); [rundown event, `platform_posix.c:404`](../ref/msquic-80a065112426bce68c1da42d026478d3e40fd45e/src/platform/platform_posix.c#L404).

The translated interlocked Ready/Running and reference-count operations remain authoritative. Queue monitor publication complements them; it does not replace them with plain managed fields or remove the worker's second EC pass. Tests must cover wake-before-wait, wake during the Running clear, and enqueue from inside a completion. Additional duplicate control notifications are harmless only because their actual callbacks drain state or wake polling; silently coalescing packet completions is not permitted.

## Destruction and reentrancy

Successful teardown follows this order, derived from the actual worker code:

1. The owning facade stops new application operations and arranges shutdown of connections, datapath producers and execution contexts. Retain all upstream pool references, pending I/O contexts and C callback storage until their completion paths release them.
2. Pool deletion releases/waits on upstream rundown. It must run on a thread whose progress is independent of the worker callbacks that release outstanding references.
3. For each initialized internal thread, core sets StoppingThread, enqueues ShutdownSqe, waits for its callback/thread exit, then deletes the thread token. Queue and all SQEs stay alive throughout the join.
4. Cleanup unregisters update-poll, then wake, then shutdown SQE. Because the consumer has joined, any residual pending control notifications may be removed without invocation. There must be no outstanding batch at this point. A producer operation already holding a host lease finishes before registration reclamation; no new producer may be admitted after closing.
5. Cleanup destroys the event queue, then EC lock. Finally core uninitializes pool rundown and frees the contiguous worker pool.
6. After all other core/socket/TLS callbacks have also drained, complete system unload and only then uninstall the host table and release its managed roots.

[Worker destroy order, `platform_worker.c:232`](../ref/msquic-80a065112426bce68c1da42d026478d3e40fd45e/src/platform/platform_worker.c#L232); [pool free order, line 441](../ref/msquic-80a065112426bce68c1da42d026478d3e40fd45e/src/platform/platform_worker.c#L441); [host unload precondition, `host.c:75`](../src/Host/host.c#L75).

Partial initialization uses the same initialized-bit checks: no uninitialized thread may be joined, but registered SQEs and an initialized queue must still be reclaimed. A thread-create failure must leave no running callback and no leaked usable token. If the thread started successfully, report success and let normal upstream teardown join it; do not return failure while a callback can still access a worker that the error path will free.

`CxPlatSqeCleanup` marks the registration closing under the queue gate, rejects later enqueue admission, removes a pending node and waits for any foreign in-flight batch/active operation to finish before clearing its token and reclaiming the record. Waiting releases the queue gate so the consumer can return the batch; registry locks never span this wait. P3 control-SQE cleanup occurs after join and should never wait on an active batch. If cleanup is attempted on its own consumer while a batch is outstanding, it must not block waiting for its own Return: that call sequence is invalid for this first contract and must be prevented by deferred owning-facade disposal. Socket notification teardown can use the implemented `PlatformSqeCleanupDeferred` helper described below; synchronous cleanup remains invalid when it would wait on its own batch.

The internal `PlatformSqeCleanupDeferred` helper handles a close requested from another completion in the same batch, or from the owning consumer itself. It immediately marks the registration closing and removes pending readiness, so future enqueue returns false. It preserves the registry token, C SQE and Completion until every already-issued CQE in the batch has run. The datapath callback must observe its own closing flag and avoid further user upcalls. `CxPlatEventQReturn` releases the complete batch, then finalizes the SQE and invokes the supplied owner-reclamation action outside the queue gate. This permits a later CQE to safely observe closing without accessing freed context. No new list allocation occurs in Return; deferred finalizers are linked through existing SQE records. The four-runtime test explicitly closes the second SQE from the first callback in a two-CQE batch, checks enqueue rejection, and proves finalization happens only after Return. Packet/socket lifecycle qualification remains the datapath worker’s separate gate.

`CxPlatThreadWait` joins actual callback termination, never just a requested-stop event. Self-join is invalid upstream, where it is asserted before `pthread_join`. Public registration close also warns that it deadlocks inside MsQuic callbacks. Callback-initiated Dispose/Close must request shutdown and arrange final blocking cleanup on an independent owner thread; it must not block the callback waiting for that cleanup. The facade cannot expose a synchronous callback-path “successful disposal” that releases roots before draining. [Thread wait, `platform_posix.c:822`](../ref/msquic-80a065112426bce68c1da42d026478d3e40fd45e/src/platform/platform_posix.c#L822); [registration close warning, `msquic.h:1158`](../ref/msquic-80a065112426bce68c1da42d026478d3e40fd45e/src/inc/msquic.h#L1158).

No host registry/queue/lifecycle lock may span an upstream Completion or user callback. Reentrant callbacks may enqueue work, signal events, or request shutdown. They cannot acquire a lifecycle lock held by a thread joining them. Event/lock cleanup likewise cannot dispose a wait primitive while its waiter is still returning.

Expected failures at status/boolean initialization boundaries return the corresponding error and roll back ownership. Managed exceptions do not unwind across the C callback contract. An unexpected failure during a void completion/wait/cleanup must latch a terminal host fault and be surfaced through the owning failure path (or terminate when safe recovery is unavailable); it must not look like a normal worker exit followed by successful continued transport operation. The exact terminal-fault reporting path is an implementation gate, not permission for success stubs.

## Locks, threads and allocation

`CXPLAT_LOCK` is recursive: native initialization explicitly requests `PTHREAD_MUTEX_RECURSIVE`. A private BCL Monitor per lock record fits that required behavior, with matched owner-thread recursion and release; a nonrecursive semaphore does not. Lock uninitialization requires no holders or waiters and must not release another thread's lock. RW locks are distinct shared/exclusive primitives; preserve repeated same-thread shared acquisition where the source permits it, avoid implicit read-to-write upgrades, and qualify their semantics separately instead of mapping every lock to one exclusive gate. [Recursive mutex, `quic_platform_posix.h:412`](../ref/msquic-80a065112426bce68c1da42d026478d3e40fd45e/src/inc/quic_platform_posix.h#L412); [RW lock contract, line 444](../ref/msquic-80a065112426bce68c1da42d026478d3e40fd45e/src/inc/quic_platform_posix.h#L444).

Use a dedicated BCL Thread for each internal worker. Copy the typed callback and context before Start, invoke once on that thread, and retain its record through join/delete. Copy the optional UTF-8 name; never retain the stack ThreadConfig pointer. Logical thread IDs must be stable and distinct for concurrently alive threads, fit `CXPLAT_THREAD_ID` (`uint32_t`) and work for callback/reentrancy checks. Ideal processor is a logical worker-selection hint, not a claim of CPU pinning: pinned Linux source itself says there is no ideal-processor API. Explicit affinity/high-priority modes remain rejected by the first public profile unless separately implemented and qualified. [Thread configuration/flags, `platform_worker.c:307`](../ref/msquic-80a065112426bce68c1da42d026478d3e40fd45e/src/platform/platform_worker.c#L307); [native Linux hint limitation, `platform_posix.c:671`](../ref/msquic-80a065112426bce68c1da42d026478d3e40fd45e/src/platform/platform_posix.c#L671).

Host allocations must provide at least 16-byte alignment for this selected ABI, including after pool-header adjustment. The overlay defines an aligned `CXPLAT_POOL_HEADER`, adds its size to allocations and returns `Header + sizeof(Header)` to the caller; its measured size and alignment are both 16. Retain its originating allocator domain and full base allocation. The BCL allocation record roots an overallocated pinned byte array and exposes its aligned interior pointer; allocation/free accounting uses that exact user pointer and original backing, never an unrooted interior pointer. Checked size/over-allocation failures return null. `CxPlatAlloc` zeroes every requested byte; `CxPlatAllocUninitialized` provides the same alignment/lifetime without promising zeros. Free accepts null and releases only its own domain's record. [Pool layout, host header line 483](../config/managed-host/inc/quic_platform_posix.h#L483); [pool allocation, line 543](../config/managed-host/inc/quic_platform_posix.h#L543); [native allocation semantics, `platform_posix.c:271`](../ref/msquic-80a065112426bce68c1da42d026478d3e40fd45e/src/platform/platform_posix.c#L271).

Do not infer stronger cache-line alignment from a source spelling: `QUIC_CACHEALIGN` is empty in the selected POSIX header. Any future type requiring more than 16 must update the allocation contract based on measured layout. Cross-picotls memory remains a separate allocator domain; copy or free through the origin provider as the TLS boundary requires. [Selected cache annotation, `msquic_posix.h:198`](../ref/msquic-80a065112426bce68c1da42d026478d3e40fd45e/src/inc/msquic_posix.h#L198).

## P6 global rundown lifetime repair

The first complete transport run exposed one retained `PlatformEvent` after
library and credential close, with zero allocations and receive leases. The
retained token exactly matched the generated
`MsQuicGlobals.MsQuicLib.RegistrationCloseCleanupRundown.RundownComplete.Handle`.
Pinned `library.c` initializes this rundown at line 517 and drains it during
normal uninitialization at line 747, but omits `CxPlatRundownUninitialize`; the
initialization failure path does call that cleanup.

The authored BCL `PlatformUninitialize` repairs only this exact event after
checking that shutdown is set, the cleanup worker has joined and its handle is
zero, and the rundown reference count is zero. It calls the existing typed event
cleanup and clears the actual generated field. Generic rundown behavior and the
upstream source remain unchanged. Every other live resource still blocks host
disposal. The peer harness now exercises three actual library open/registration/
close cycles while retaining an unrelated event, checks its preservation and
host-disposal rejection, then explicitly releases that unrelated owner. This control passes in each endpoint of the 20-pair optimized JIT transport
campaign. Raw/optimized NativeAOT transport revalidation remains pending.
