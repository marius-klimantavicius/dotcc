This qualified finite fixture exercises the original IEEE 802.1D bridge and example FDB using in-memory Ethernet frames. No external network is involved.

`src/port/bridge_service.c` is an authored include-wrapper, not an upstream source patch. The public bridge API provides initialization, adding ports, and static FDB operations; it exposes neither removal/deinitialization nor the private dynamic FDB timer callback. A typed override of public functions cannot name the private callback/state needed to cancel and release it. Including the two unchanged original C files in one translation unit makes that lifecycle boundary available while preserving their forwarding, learning and aging algorithms.

All lifecycle calls require the owner's core context. The owner must stop port ingress and drain already posted core input callbacks before stopping. Stop validates every port attachment before modifying anything, cancels the exact recurring FDB timeout, restores input/client-data/ETHARP ownership, removes the bridge netif, then frees the private FDB and bridge allocations. Repeated stop succeeds; freeing before stop fails. A per-translated-owner registry rejects foreign/unknown handles before dereferencing them. The context itself is released only by the explicit free call. Raw borrowed users retain responsibility for netif and callback lifetimes.

The product replaces both original translation units with this wrapper. The managed ordinary consumer registers its bridge service through StartService and verifies two-owner isolation and queued-loopback stop. All three product profiles pass raw/processed JIT/NativeAOT in110105-df4730c6,110524-6852b698,111004-d11b3587. A broader public owning bridge API remains separate from this test-owned service.

`lwip_owned_bridge_barrier` always posts a real TCP/IP callback and waits for its semaphore outside the core; `tcpip_callback_wait` alone is insufficient as a FIFO barrier in the core-locking profile. Call it after stopping ingress, then stop on the core, call it again before freeing the retained netif context. Stop drains the bridge's own loopback queue through the original `netif_poll`. Core-locking callers must release the core lock before either barrier. On barrier/admission failure, retain the context and retry; never free a possibly queued callback target.

Native timer advancement polls all original netifs each tick. The initial baseline failure (336 bytes) was traced to three ND packets on the built-in loopback netif, caused by advancing 602 seconds without servicing the NO_SYS loopback input. The allocator backtraces and failed report are preserved under `artifacts/bridge-unpolled-loopback-*`. This is a fixture scheduling correction, not discarded bridge allocations or an upstream repair.
