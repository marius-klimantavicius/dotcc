# Static function deduplication

Status: canonical portable products and the selected Linux x64
raw/processed JIT/NativeAOT matrix qualified, 2026-10-20.

The zstd recipe explicitly adds `--deduplicate-static` alongside its existing
inline deduplication, literal pooling and 256 KiB source splitting. Shared
campaign and standalone CLI defaults are unchanged. The portable source units,
primitive rules, owning API and selected codec features retain their existing
scope. Generated C# is regenerated by the compiler rather than edited.

This follow-up measures emitted source and qualified binary sizes. It does not
repeat timing or claim a performance improvement over
[direct intrinsic emission](direct-intrinsics.md).

Function counts and function-source bytes use only `Zstd.[0-9]*.cs`, excluding
the primary `Zstd.cs` runtime/type/global file in both variants. Counts inspect
the generated public static method declarations with brace bodies in that
format. All-source bytes include every generated `.cs` file. NativeAOT sizes
are the complete rooted `ManagedTests` executable, including the unchanged
harness and owning API; they are not isolated codec text sizes. Unit-suffixed
counts also reflect canonical naming; the actual declaration reduction is 340
per form. Function splits decrease from ten to nine per form.

All 20 observed hash families (`ZSTD_hash3` through `ZSTD_hash8`, their `Ptr`
and `PtrS` forms, `ZSTD_hashPtr` and `ZSTD_hashPtrSalted`) decrease from 12
declarations to one per form. Removing translation-unit suffixes solely for
diagnostic body grouping gives one body per reference family. Exact file digests
remain unnormalized. This grouping is evidence about the emitted reference; the
compiler's semantic safety rules determine eligibility for actual deduplication.

## Reproduction and acceptance

The comparison helper performs no builds or execution of codec binaries. It
requires a successful complete raw/processed JIT/NativeAOT receipt, records exact
source and binary sizes, and rehashes the preserved baseline sources and
binaries. It requires unchanged selected sources, primitive selection and
production inputs other than the recipe, fewer function declarations and source
bytes, and one emitted declaration for each `ZSTD_hash4Ptr` through
`ZSTD_hash8Ptr`. A disabled or ineffective static deduplication option fails
the comparison.

Use fresh evidence output paths. `--source-tree` reads the byte-preserved delivery
tree, allowing the reference counts to be reproduced after the canonical outputs
have been replaced. Without that option, capture reads the receipt's canonical
products and requires their original hashes. Qualify the new products and compare
afterward:

```bash
python3 -B zstd/tests/static_dedup.py --receipt zstd/artifacts/campaign/20261020-065322-dcdf2024/receipt.json --source-tree zstd/artifacts/campaign/20261020-065322-dcdf2024/copied-delivery/tree --output zstd/artifacts/static-dedup-repeat/baseline.json
DOTCC_CAMPAIGN_COMMAND_LOCKS=production bash zstd/scripts/verify.sh --tools reuse --fetch never --form all --mode all --rid linux-x64 --jobs 2
DOTCC_CAMPAIGN_COMMAND_LOCKS=production python3 zstd/tests/delivery.py --receipt zstd/artifacts/campaign/NEW_SUCCESSFUL_RECEIPT/receipt.json --output zstd/artifacts/static-dedup-repeat/copied-delivery
python3 -B zstd/tests/static_dedup.py --receipt zstd/artifacts/campaign/NEW_SUCCESSFUL_RECEIPT/receipt.json --baseline zstd/artifacts/static-dedup-repeat/baseline.json --output zstd/artifacts/static-dedup-repeat/comparison.json
```

`--tools reuse` must select freshly built tools containing the static
deduplication implementation. Shared production command locks serialize build
windows; emission has two workers, native preparation has two jobs and managed
builds use one MSBuild node. The complete verification and copied-delivery
reports remain the behavioral and delivery gates.
